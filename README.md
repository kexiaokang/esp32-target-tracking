# ESP32 目标追踪（颜色识别 + 云台跟踪）

用 **ESP32-CAM** 做实时颜色目标识别，驱动两轴舵机云台自动跟随目标。手机连上板子自带的热点，打开网页就能看画面、调参数、手动控制。

> 网页界面：上方实时画面（**绿框**标出识别到的目标，**青十字**是质心，**黄十字**是画面中心），
> 下方是模式切换、舵机使能/跟踪、方向微调、增益死区等参数滑块。

---

## 功能

- **颜色识别跟踪**：自动找画面里最红的目标，或标定任意颜色
- **亮度模式**：Otsu 自动分亮暗，追"少数派"那一类（白墙前追黑物、黑桌上追白纸）
- **双工作模式**（网页一键切换）
  - 跟踪模式：YUV 原始像素做识别，**26.6 fps**
  - 流畅模式：JPEG 硬件直出，**29.9 fps**（不做识别，纯看画面）
- **舵机 50 Hz 独立任务**：与摄像头帧率解耦，连续平滑运动
- **网页实时调参**：增益、死区、限速、面积门限、机械限位全部在线可调，不用重烧
- **故障自诊断**：串口打印各阶段耗时（抓帧/特征/找目标/编码），网页显示重启次数和原因

## 硬件清单

| 部件 | 型号 | 说明 |
|------|------|------|
| 主控 | ESP32-CAM (AI Thinker) | 必须带 **PSRAM**，否则摄像头起不来 |
| 摄像头 | OV3660 / OV2640 / GC2145 | 代码自动识别型号，三种都支持 |
| 舵机 ×2 | SG90 / MG996R | 上下 + 左右各一个 |
| 电源 | 5V ≥2A | **舵机必须独立供电**，见下方接线 |

## 接线

| 从 | 到 | 说明 |
|---|---|---|
| **上下**舵机 信号线（橙） | CAM **IO13** | 代码里 `TILT_PIN = 13` |
| **左右**舵机 信号线（橙） | CAM **IO14** | 代码里 `PAN_PIN = 14` |
| 两个舵机 红线（+） | 外部 5V 正极 | **不要**从板子 5V 脚取电 |
| 两个舵机 棕/黑线（−） | 外部 5V 负极 | |
| 外部 5V 负极 | **CAM GND** | **必须共地**，否则舵机乱抖或不动 |
| CAM 5V / GND | USB 或独立 5V | 只给板子自己供电 |

```
  ┌─────────────┐         ┌──────────────┐
  │ 5V 2A 电源  │         │  USB 5V      │
  │  +      −   │         │  (给板子)     │
  └──┬──────┬───┘         └──────┬───────┘
     │      │                    │
     │      └──────────┬─────────┘   ← 共地
     │                 │
   舵机红            CAM GND
   舵机棕 ────────────┘
```

> **共地是硬要求**。两块电源不共地时，PWM 信号没有参考电平，现象是"舵机疯狂抖"或"完全不动"。
>
> 舵机不要和板子共用一条面包板电源轨 —— 舵机堵转瞬间 1A 以上，压降会把板子拉到欠压复位。

详细供电排查见 [WIRING.md](WIRING.md)。

## 环境准备

### 1. 安装 Arduino IDE

[arduino.cc/en/software](https://www.arduino.cc/en/software) 下载即可，1.8.x 和 2.x 都行。

### 2. 安装 ESP32 开发板支持 —— **版本必须是 2.0.17**

> ⚠️ **这是最关键的一步，装错版本一定编译失败。**
>
> 代码里用了 `ledc_timer_config` / `ledc_channel_config` / `ledcDetachPin` 等底层 API，
> 这些在 **esp32 core 3.x 里签名变了**，会报一堆 `no matching function` 错误。

步骤：

1. 打开 **文件 → 首选项**
2. "附加开发板管理器网址" 填入：
   ```
   https://espressif.github.io/arduino-esp32/package_esp32_index.json
   ```
3. 打开 **工具 → 开发板 → 开发板管理器**
4. 搜索 `esp32`（作者 Espressif Systems）
5. **点开版本下拉，选 `2.0.17`**，然后安装

> 不要直接点"安装"装最新版（3.x），一定要先选版本。

### 3. 开发板设置

打开 `WebTrack/WebTrack.ino` 后，在 **工具** 菜单里设置：

| 项目 | 值 |
|------|-----|
| 开发板 | **AI Thinker ESP32-CAM** |
| Upload Speed | 115200（烧录失败就降到 57600） |
| Flash Frequency | 40MHz |
| **Partition Scheme** | **Huge APP (3MB No OTA/1MB SPIFFS)** |
| **PSRAM** | **Enabled** |
| Port | 板子对应的 COM 口 |

> **PSRAM 必须开**。关掉的话摄像头初始化会失败，网页上会显示"摄像头没就绪"。
>
> **Partition Scheme 必须选 Huge APP**。默认分区只有 1.2MB，本程序编译后约 915KB，
> 加上 OTA 预留可能不够。

### 4. 库依赖

**不需要额外装库。** 用到的 `WiFi.h`、`WebServer.h`、`esp_camera.h`、`driver/ledc.h`
全部包含在 esp32 core 里。

## 编译与烧录

### 用 Arduino IDE

1. 打开 `WebTrack/WebTrack.ino`
2. 选好开发板和端口
3. 点 **上传**（→ 按钮）

**烧录时常见问题**：

| 现象 | 办法 |
|------|------|
| `Failed to connect to ESP32` | 按住板子上的 **IO0** 键再点上传，看到 `Connecting...` 后松开 |
| 烧录到一半断开 | Upload Speed 降到 57600 |
| 端口不出现 | 换一根 **能传数据** 的 USB 线（很多线只能充电） |
| 一直复位 | 拔掉舵机信号线再烧（舵机耗电会拉垮电压） |

### 用 arduino-cli（可选）

```bash
arduino-cli core install esp32:esp32@2.0.17
arduino-cli compile --fqbn esp32:esp32:esp32cam WebTrack
arduino-cli upload  -p COM3 --fqbn esp32:esp32:esp32cam WebTrack
```

## 上电使用

### 1. 连热点

板子上电后自建热点：

- **热点名**：`ESP32CAM-TRACK`
- **密码**：`12345678`
- **网页地址**：<http://192.168.4.1>

> 安卓提示"此 WLAN 无法访问互联网"→ 点**保持连接**。
> 打不开网页 → 关掉手机**移动数据**，有些系统会强制走 4G。

### 2. 第一次测试顺序

**上电后舵机是"松"的**（程序故意不发 PWM），不响、不烫、可以用手掰。

1. 连热点，打开网页
2. 用手把云台摆到大概中间
3. 点 **「使能舵机」** → 舵机回 90° 并保持
4. 点 **「上 ▲ / 下 ▼ / 左 ◀ / 右 ▶」** 逐个试（每次 5°）
   - 确认 **IO13 动的是上下、IO14 动的是左右**
   - 方向反了点「左右取反」/「上下取反」
   - 舵机动的是另一个轴 → 点「舵机接线对调」
5. 一直点到听见"嗡嗡"顶住，就往回收 5°~10°，那是机械限位
6. 把范围填进「机械限位」四个滑块
7. 点「自动找最红」→ 点「开始跟踪」

> 任何时候听到舵机一直响却不转，**立刻点「松开舵机」**，那是顶死了会烧。

## 两种工作模式

网页顶部两个按钮，点了会重新初始化摄像头（约 0.5 秒），页面自动刷新。

### 跟踪模式（默认）

- 摄像头输出 **YUV422 原始像素**（160×120）
- 自己算色度做颜色识别 → 能自动跟踪
- 网页预览 26.6 fps

### 流畅模式

- 摄像头输出 **JPEG**（320×240），硬件压好的，CPU 零成本
- 画面直接转发给浏览器，29.9 fps
- **不做识别**，只能用方向按钮手动控制舵机

> **为什么不能两个都要？**
> 颜色识别必须拿原始 YUV 像素（红度 = V − U），JPEG 是压缩过的解不出来。
> 而 sensor 一次只能输出一种格式，所以只能二选一。

## 性能实测

| 模式 | 分辨率 | 格式 | XCLK | 帧率 |
|------|--------|------|------|------|
| 跟踪 | 160×120 | YUV422 | 24MHz | **26.6 fps** |
| 流畅 | 320×240 | JPEG | 24MHz | **29.9 fps** |

跟踪模式的耗时分解（串口每秒打印）：

```
抓帧 29.3ms   ← 瓶颈在这，sensor 输出一帧就要这么久
特征  5.9ms   ← 76800 像素降采样到 80×60 网格
找目标 1.6ms  ← 连通域 + 质心
编码  ~8ms    ← 只在网页有人看时执行
```

**为什么到不了 60 fps**：ESP32 的摄像头并口（I2S DMA）吞吐约 2.25 MB/s，
YUV422 一帧 38KB，光搬运就要 29ms。这是硬件带宽限制，换摄像头也没用
（瓶颈是 ESP32 的并口，不是 sensor）。真要 60fps 得上 ESP32-S3。

## 网页控件说明

| 控件 | 作用 |
|------|------|
| **流畅模式 / 跟踪模式** | 切换工作模式 |
| **使能舵机 / 松开舵机** | 上电默认松的，使能后才发 PWM |
| **开始跟踪 / 停止跟踪** | 舵机没使能时会自动帮你使能 |
| 上/下/左/右 | 手动微调 5°，会停掉跟踪 |
| 回中 | 两个舵机回 90° |
| 增益（度/秒） | 误差满格时云台转多快。大了会来回摆，小了追不上 |
| 死区 | 目标在中心这个比例内不动，防抖 |
| 限速（度/秒） | 舵机最大转速 |
| 最小/最大面积 % | 目标占画面比例范围，排除噪点和背景 |
| 机械限位 4 个滑块 | 防止顶死 |
| 左右取反 / 上下取反 | 方向反了用 |
| **舵机接线对调** | 两个舵机接反时软件换过来，不用重插线 |
| 补光灯 0~100 | 板载白光 LED，默认关 |

画面里：**绿框** = 识别到的目标，**青十字** = 质心，**黄十字** = 画面中心。

状态栏还会显示当前配置（方向正/反、接线是否对调）、误差、舵机速度、目标角，
调不动的时候看这几行就能定位问题。

## 常见问题

| 现象 | 原因 / 办法 |
|------|------------|
| **编译报 `no matching function`** | esp32 core 装成 3.x 了，卸载重装 **2.0.17** |
| 上传失败 `Failed to connect` | 按住 IO0 再上传 |
| 网页显示"摄像头没就绪" | PSRAM 没开 / FPC 排线没插紧 / 供电不足 |
| **手机搜不到热点** | ① 2.4GHz，下拉刷新；② 离板子太近（<30cm）反而搜不到，拿远半米；③ **最可能：供电不足** |
| 舵机每隔一两秒抽一下 | **板子在反复重启**，供电塌了。看状态栏"启动第 N 次"是否一直涨 |
| 舵机完全不动 | 没共地 / 信号线没接 IO13、IO14 / 舵机没独立供电 |
| 舵机一直响不转 | 顶到机械限位了，点「松开舵机」，收窄限位 |
| 云台越追越偏 | 点「左右取反」/「上下取反」；或点「舵机接线对调」 |
| 云台来回摆 | 增益调小，或死区调大 |
| 跟踪跟不上 | 目标动太快，超过 26fps + 舵机速度的极限 |
| 画面撕裂/错位 | 旧固件 bug，已修（`send_P` 的长度参数） |

### 怎么判断板子是不是在重启

状态栏有 **「启动第 N 次　上次重启：xxx」**：

- N **一直往上涨** = 正在反复复位
- 上次重启显示「欠压复位」= 供电塌了，必须分开供电
- 显示「程序崩溃」/「看门狗」= 固件问题

**验证方法**：把两颗舵机信号线从 IO13/IO14 拔掉（电源线可以留），
再点「使能舵机」和方向键。如果页面不卡了、启动次数也不涨了 → 确认是舵机拉垮了电压。

### WebTrack.ino 内部结构

| 区块 | 内容 |
|------|------|
| 配置区 | 引脚、热点、舵机 PWM、识别参数（可调默认值都在这里） |
| 舵机 | `servoInit/servoAttach/servoRelease/servoWrite` + **`servoTask`（50Hz 独立任务）** |
| 摄像头 | `cameraTry/initCamera/reinitCamera`，按模式选格式和分辨率 |
| 识别 | `buildFeatures`（降采样到 80×60 网格）→ `findTarget`（连通域 + 质心） |
| 控制 | 速度式控制律，输出角速度给 `servoTask` 积分 |
| 网页 | `INDEX`（HTML/CSS/JS 全内嵌）+ `handleApi/handleJpg/handleSet` |

### 想改的关键参数


## 已知限制

- **不能 60 fps**：I2S 带宽限制，见上文性能实测
- **跟踪模式画质较低**：160×120，为了换帧率；流畅模式是 320×240
- **流畅模式不能跟踪**：JPEG 格式做不了颜色识别
- **舵机行程受机械限位约束**：默认 60°~120°，按实际云台调
